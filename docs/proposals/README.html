Tantra Enterprise Proposals

Turn the notes from a 30-minute Enterprise Evaluation Call into the written proposal the client gets within one business day. One notes file in, one branded PDF out.

Private repo. Real proposals never enter git: proposals/ is in .gitignore.

Quick Start

python3 generate.py examples/fictional-call-notes.md --paper both
open proposals/harrow-finch-advisory/proposal.pdf

For a real client:

mkdir -p proposals/acme-ltd
# write proposals/acme-ltd/notes.md in the format below (it stays out of git)
python3 generate.py proposals/acme-ltd/notes.md --paper a4 --strict

--strict refuses to build while any amber FILL box is left (payment terms, start date, an unknown closer, a closer with no Proposal Review link, or a DRAFT status in config/offer.json), so a draft can never be sent by accident. Dates written as YYYY-MM-DD print as "4 Nov 2026". Use --paper letter for US clients, --paper both for both.

Output: proposals/<client-slug>/proposal.html (self-contained: fonts and logo embedded) and proposal.pdf.

The Sections (In the Order of Adi's Reference Layout)

  1. Title card: logo, "Tantra Enterprise Revenue Engine Proposal for ", date and call date (screen view adds the left Contents rail; print adds a Contents panel on page 1)
  2. Introduction: client person card (monogram), the letter from Adi, Adi's person card (avatar)
  3. Scenario Overview: "Where You Are Today" (the client's quotes, goal, the leak) beside "Our Approach", a pull quote, then the numbers table
  4. The Tantra Enterprise Framework: four phase chips, the rule we build by, the phase-by-phase story
  5. Proof: Growth Idea and FintechCircle, measured only (not in the reference layout; required by the brief)
  6. Recommended Funnel Strategy: the six stages as numbered rows, the leak tagged "Fix first", plus the AI agent row
  7. Your 3-Month Implementation Plan: four phases, week columns, a milestone per phase, the client's plan notes
  8. Coaching and Support After the Build
  9. Your Role: during the build (your team and Tantra side by side, your named people), after hand-over
  10. Your Investment: recommendation and why, the plan card (price, includes, payment terms), note
  11. Tools and Third-Party Costs: included and not-included table
  12. Ongoing Funnel Operations: the two roles on the client side after month 3
  13. What We Commit To: weekly measurement, and no promised results (the reference's guarantees slot; we offer no guarantee)
  14. Proposal Review and Next Steps (the next step is the Proposal Review call with the closer, on their own Cal.com link, where we decide together; then agreement and payment link, then week 1), When You See First Results, sign-off; then Ready to Get Started with both signature blocks

Call-Notes Fields

Write the notes as markdown (front matter plus ## field sections, see examples/fictional-call-notes.md) or as JSON with the same keys.

Field Required Format Prints as
client_company yes text Title card, footer, acceptance. Also sets the folder slug
client_contact yes first name Title card and the note from Adi
client_role no text Under the contact name on the person card
call_date yes YYYY-MM-DD Title card and introduction
closer yes Conor or Scott Introduction letter and next steps. Anyone else blocks --strict
proposal_date no YYYY-MM-DD Title card. Default: today
valid_until no YYYY-MM-DD Title card, only if given. Never invent a deadline
start_date no text Next steps. Missing: amber FILL box
payment_terms no text Investment. Missing: amber FILL box. Adi sets these
conversion_mechanism no text, for example a weekly live webinar Scenario Overview and Funnel Strategy. Default: "chosen with you in weeks 1 to 2"
leak_stage yes traffic, pages, nurture, conversion, pipeline or growth Scenario Overview, Funnel Strategy (Fix first), the plan and Investment
leak_detail yes one paragraph Scenario Overview (Where Revenue Leaks)
situation yes bullets, the client's own words Scenario Overview, one quote per bullet
goal yes one paragraph Scenario Overview (Your Goal)
numbers yes bullets Label \| today \| target (JSON: [{label, today, target}]) Scenario Overview table
client_team no bullets Name, Role \| what they own (JSON: [{who, owns}]) Your Role (Your People on This)
plan_notes no bullets 1: note to 4: note (JSON: {"1": ["note"]}) Under the matching phase in the implementation plan
proof no growth-idea, fintechcircle Proof. Default: both. Anything else is refused
example no true Adds a "Fictional example" band to the title card

Where the Facts Come From

  • Price, includes, host and closer names, and each closer's Proposal Review link (booking.call2.<closer>_url): ~/tantra-enterprise-webinar/deliverables/_shared/funnel-config.json when it exists (set TANTRA_FUNNEL_CONFIG to point elsewhere), else config/offer.json. The generator says when the two differ.
  • Proof: ~/tantra-enterprise-webinar/deliverables/_shared/PROOF_PACK.md section 3, copied into config/proof.json. Measured lines only.

Adi to Confirm Before the First Real Proposal

  • Payment terms (in full on signature, or instalments). Until set, every proposal shows a FILL box.
  • The "Not included" list and cost table, the 3-month plan, and the Your Role and Ongoing Operations sections. Each prints with an amber FILL note and blocks --strict until Adi confirms it and its status in config/offer.json (not_included_status, plan_status, roles_status) is changed from DRAFT to CONFIRMED.
  • Whether a "valid until" date should be standard. Left off unless the notes give one.
  • Each closer's Proposal Review link (https://cal.com/<username>/proposal-review, set up per deliverables/18-19-booking/19-calcom-round-robin.md, section 8). Until it is in the funnel config (booking.call2.conor_url, scott_url), the next steps show an amber FILL box and --strict blocks.

Reference Check

Rebuilt 2026-11-05 to mirror Adi's own proposal layout at /Users/adithyamurali/proposal design/proposal_template.html (structure, section order, layout and formatting; Tantra palette and fonts). That file holds a real client's proposal, so it was read for structure only. Every file here was scanned against its visible text (141 proper nouns, 96 numbers and amounts, 3,327 six-word phrases): 0 hits on any client name, person, amount or phrase. The only matches were generic words (Sales, Timeline, Results), CSS values, and approved lines (250+ brands, Pro $99). The compare/ images contain reference renders and are git-ignored.

Deviations from the reference, and why: - Proof section added after the framework: the brief requires measured proof; the reference has none. - Pricing: one plan card, not three. Tantra Enterprise is the only offer. No guarantee badges and no payment-plan prices: we offer no guarantee and payment terms are a FILL until Adi sets them. - Guarantees slot kept as "What We Commit To", which says plainly that results are not promised. - Tool costs: the table shows included and not-included items with no prices, because we have no sourced costs. - Ongoing roles show no hours or staffing costs (unknown). Contents rail is screen-only; print gets a Contents panel. The booking calendar embed becomes the numbered next steps; the sign button becomes signature blocks.
