CRM contract: the one data shape every integration uses

Every page form, WebinarJam export, poll, Cal.com webhook, nurture tool and retargeting script reads or writes the CRM through this contract. Item 23 builds the sheet and the Apps Script web app that implements it. Other items only POST events to it or read its tabs. Change this file first, then the code.

Sheet: "Tantra Enterprise CRM" (Google Sheets, in Adi's Drive)

Tab One row per Written by
Contacts email (lowercased, the key) every event (upsert)
Webinar email x webinar date registration, attendance import, polls, CTA clicks
Pipeline deal (one open deal per email) booking, call outcome, proposal, won, lost
Events event (append only, never edited) every POST
Sequences email x sequence step nurture tools, follow-up runner
Lists config: dropdown values, closer emails and WhatsApp numbers, booking_url, onboarding_link item 23
Summary formulas only: counts per stage and per webinar segment item 23 (never written by events)

Pipeline stages (playbook, in order)

1 New Lead, 2 Call Booked, 3 Confirmed, 4a Showed, 4b No-Show, 5 Proposal Sent, 6 Follow-Up, 7 Closed Won, 8 Closed Lost, 9 Nurture.

Playbook fields: Source (Ad, organic, referral, old list, inbound DM, webinar), Setter, Closer, Call date, Show status (Showed, No-Show, Rescheduled), Deal value, Lost reason (price, timing, competitor, not a fit), Next follow-up date.

This funnel sends WhatsApp where the playbook says SMS (the Enterprise booking text was corrected to "no SMS" on 2026-09-30). Same sending-hour rule: 8am to 8pm in the lead's timezone, for every WhatsApp step including live-day reminders (outside the window the email goes and the WhatsApp is skipped; waiving this for live-day steps is Adi's decision, logged in BLOCKERS.md). STOP or "stop" in any channel tags the contact Do Not Contact and ends every sequence.

Call 2 (Adi, 2026-11-05)

Pipeline order: Call Booked (Call 1) > Confirmed > Showed > Proposal Sent (proposal within one business day, Call 2 link inside) > Call 2 Booked > Call 2 Showed > Closed Won or Lost. A booking.created with call 2 never moves a deal back to Call Booked: it sets call2_date and the deal stays in Proposal Sent with sub-status Call 2 Booked. Fields: call2_date, call2_status (Booked, Showed, No-Show, Rescheduled), call2_cal_uid, call2_join_link.

Webinar segments (computed on the Webinar tab)

  • track column: written only as replay (a CANT quick reply moves the contact to the replay track). The post-webinar tracks key off the segment, not this column.
  • registered: has a webinar.registered event for that date.
  • Attendance rule (one rule for items 17, 23 and 27): if WebinarJam marks the person as attended, they attended, and minutes_in_room is floored at 1 (a blank or 0 time becomes 1). Only registrants WebinarJam marks as not attended are no_show.
  • attended: attended per the rule above.
  • early_leaver: attended and left before minute 25 (webinar.retarget_cutoff_minute in funnel-config.json).
  • stayed_to_offer: attended and minutes_in_room >= 25.
  • no_show: registered, minutes_in_room = 0.
  • retarget_until: webinar date + 42 days for early_leaver and no_show (6 weeks), then the contact drops out of retargeting unless it books or replies.

Registration flow

Registration page form, then the register Worker (item 17) which registers the person in WebinarJam (personal join_url), then posts webinar.registered to the CRM endpoint. The page never posts to the CRM directly (that would skip WebinarJam and double the event).

The endpoint

POST {integrations.crm_webhook_url} with Content-Type: application/json (Apps Script web app, doPost). Body:

{
  "event": "webinar.registered",
  "email": "person@company.com",
  "ts": "2026-11-12T15:04:05Z",
  "source": "registration_page",
  "webinar_date": "2026-11-12",
  "data": { "first_name": "Sam", "company": "Acme", "phone": "+44...", "utm_source": "calendar", "utm_campaign": "E1-v1" }
}

A shared secret travels as ?k= on the URL (stored in Script Properties, never in this repo). The script answers {"ok":true} or {"ok":false,"error":"..."}.
