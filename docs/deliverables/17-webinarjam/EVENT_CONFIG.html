WebinarJam Event Configuration Sheet

One WebinarJam webinar runs every week of this funnel. Fill it once, field by field, in WebinarJam's own order. Values written as key.path come from deliverables/_shared/funnel-config.json: type the current value from there. "Confirm in the WebinarJam dashboard" marks anything no source could settle. Source tags are listed at the end: [SOP] frames from the SOP #4 recording, [CMP] the platform comparison, [H] a help-centre article.

Field Value

The register Worker reads the session list from the API and puts each person in the first session that has not ended, so nobody types a schedule ID (the SOP did this by hand with curl [SOP 48:21]). Note the API schedule ID differs from the one shown in the Schedules tab [H 15370150].

3. Registration

People register on our page (item 13). The page posts to the register Worker at integrations.register_worker_url (integration/register.mjs), which calls WebinarJam's /register endpoint for each person; that returns their unique live room link [H 15370151], and the Worker then posts webinar.registered with that join_url to the CRM. WebinarJam's own page stays unused, but the modules below still apply to API registrants.

What the Worker sends to /register: webinar_id, schedule (the next session that has not ended), first_name (or "there" if blank), email, last_name if given, and timezone_id when needed. WebinarJam requires timezone_id for registrants in Texas (2 = Mountain, 3 = Central) [H 15370151]. We only know the browser's time zone, so US Central zones (America/Chicago and its Indiana and North Dakota variants, America/Menominee) send 3 and US Mountain zones (America/Denver, America/Boise, America/Phoenix) send 2; everyone else sends none. Confirm in the WebinarJam dashboard with one test registration from a Central time zone browser.

Abuse guard on the Worker: it answers only the funnel domain's Origin (403 otherwise), checks a Cloudflare Turnstile token server-side, accepts only source: registration_page from the web, and caps every field length. Add a Cloudflare rate-limit rule as well (README step 5).

4. Notifications

Decision: WebinarJam sends one email, the sign-up confirmation. Tantra sends everything else.

  • Items 15b (pre-webinar) and 22 (post-webinar) already run every reminder and follow-up by email and WhatsApp from Tantra, timed to our rules. Seven WebinarJam emails on top (the SOP's set [SOP 30:00 to 31:00]) would double every touch.
  • The confirmation stays because it is the one message only WebinarJam can always get right: it carries the person's unique link even if the CRM or Tantra is down, and WebinarJam re-sends nothing on repeat registrations [H 15370012]. Our thank-you page already tells people "Your personal join link is on its way from WebinarJam" (item 13).
  • The Worker puts each person's personal link on webinar.registered as join_url (CRM_CONTRACT), so Tantra's own reminders (15b uses {{join_url}}) carry the same link.
