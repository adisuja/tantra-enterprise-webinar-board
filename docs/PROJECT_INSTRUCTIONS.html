Tantra Enterprise Webinar: project instructions

This project builds the weekly webinar funnel that sells Tantra Enterprise. It is separate from the 3-Day AI RevOps Workshop project (~/tantra-redesign) and from the content project (~/tantra-content). (This file is the CLAUDE.md text, saved under this name because the rules guard blocks writing CLAUDE.md.)

Every session starts here

  1. Read context/00-INDEX.md (key facts, benchmarks, rules, open questions, file map), then only the context files the task needs.
  2. Open tasks/tasks.json, find the item Adi names (1 to 27, with 15a and 15b), and read its brief, references and context list.
  3. Read BRIEF.md for Adi's own words when wording matters.

Working a task

  1. No task starts until Adi shares its context and asks for it. Do not plan, analyse or prepare tasks ahead of that.
  2. Work only the task Adi names. Put outputs in deliverables/<item>-<slug>/, set its status in tasks/tasks.json, then rebuild and publish the board: python3 board/build.py && bash board/publish.sh.
  3. Pages ship with verified, cache-busted review links for every state.
  4. A step only Adi can do (sign-in, password, key, payment, creating an account): do everything before it, then give him one short block with the full URL, the field and what to paste or click.

Rules (Adi's; never break them)

  • Reference first (Adi, 2026-11-05, central). Every element mirrors the reference Adi gave for it: its structure, section order, layout, formatting and visual elements, as closely as possible. Only the colours and fonts change to Tantra's (usetantra.com tokens), and the words and proof are ours. Never fall back to usetantra.com's own page design. Before building, write a section-by-section mirror map from the reference; verify with side-by-side screenshots. Reference map per item: REFERENCE_MAP.md.
  • No em dashes or en dashes in anything Adi or a reader sees.
  • No AI slop. Copy reads like Brian Dean (I/you, a specific pain first), in an enterprise tone.
  • Never invent a statistic, testimonial, client result or funnel element. Approved proof only (see 00-INDEX).
  • Never change a live account (LinkedIn, Facebook, X, CRM, Workspace) unless Adi asks for that change in this conversation. Never post or send.
  • Never write a Slack or team message unless Adi asks.
  • Keys and passwords live in ~/.config/tantra/keys/ only. Never print or commit them. Never commit prospect, attendee or client personal data.
  • Social sites (LinkedIn, X, Facebook, Instagram, Reddit, YouTube) are read through Agent Reach only, never fetched directly.
  • Never push, PR or merge on any Usetantra/* repo.
