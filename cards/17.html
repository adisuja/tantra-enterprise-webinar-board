3. Registration

People register on our page (item 13). The page posts to the register Worker at integrations.register_worker_url (integration/register.mjs), which calls WebinarJam's /register endpoint for each person; that returns their unique live room link [H 15370151], and the Worker then posts webinar.registered with that join_url to the CRM. WebinarJam's own page stays unused, but the modules below still apply to API registrants.

What the Worker sends to /register: webinar_id, schedule (the next session that has not ended), first_name (or "there" if blank), email, last_name if given, and timezone_id when needed. WebinarJam requires timezone_id for registrants in Texas (2 = Mountain, 3 = Central) [H 15370151]. We only know the browser's time zone, so US Central zones (America/Chicago and its Indiana and North Dakota variants, America/Menominee) send 3 and US Mountain zones (America/Denver, America/Boise, America/Phoenix) send 2; everyone else sends none. Confirm in the WebinarJam dashboard with one test registration from a Central time zone browser.

Abuse guard on the Worker: it answers only the funnel domain's Origin (403 otherwise), checks a Cloudflare Turnstile token server-side, accepts only source: registration_page from the web, and caps every field length. Add a Cloudflare rate-limit rule as well (README step 5).
