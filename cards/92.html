Card 92: the weekly webinar cycle

The webinar runs every Thursday at 11:00 UK time. This card makes the whole funnel move to the next session by itself, checks every part of it each week, and runs a fast end-to-end test inside the CRM. Daily or fortnightly runs work the same way: set webinar.cadence (daily, weekly, fortnightly) or webinar.cadence_days in deliverables/_shared/funnel-config.json. A week with no session goes in webinar.skip_dates.

The weekly timetable (workflow Webinar weekly cycle)

When (UTC) Job
Every day 12:20 If a session just ended: rebuild and deploy the pages for the next one, move the CRM tracking campaign on, then run the full check. Otherwise only check
Monday 09:10 Full check plus the fast end-to-end test (dry run)
Wednesday 09:10 Full check plus the fast end-to-end test, live to the team's test contacts when the repository variable E2E_LIVE is 1
Any time Actions, Webinar weekly cycle, Run workflow: check, roll, e2e, e2e-live or all

Every run writes its report to the run's summary page and to the dashboard database (table cycle_checks), and fails (GitHub emails the owner) when a check fails.

What the check covers

Pages up and showing the next session; registration page date text; the .ics file; the Tantra Plans coupon deadline; WebinarJam's open sessions (at least 4 ahead); registrations since the last session reaching WebinarJam and the CRM; the CRM Webinar pipeline and stages; every webinar sequence's status, test mode, event rule and tracking campaign; one-off reschedule events in the past; every WhatsApp template used by an active sequence approved; senders running; AI calling on; the tracking pipeline healthy; the CRM funnel definition active; the dashboard rebuilt within a day; the funnel map's status date.

The fast end-to-end test in the CRM

node cycle.mjs e2e (dry run) or --live:

  1. Makes or reuses the pipeline Webinar E2E test (fast) with the same stages as the Webinar pipeline.
  2. Copies every live webinar sequence into it as E2E fast: (name), fresh from the real ones each run, with the session 12 minutes away and every timing squeezed (3 days becomes 8 minutes, 1 day 4, an hour or less 1). Tag triggers stay inside the test pipeline, so the real sequences never see a test deal.
  3. Creates three test deals: one goes to Attended (with the survey tag), one to Missed, one to Webinar Reschedule.
  4. Waits until every step has run, then fails any step that failed or was skipped for a reason that is not expected (no phone on a dry-run deal, a condition, consent).
  5. Checks the tracking events for the test deals, then deletes them.

Dry run: test deals use example.com addresses and no phone, and the copies are in test mode, so nothing is sent. Live: the deals use E2E_EMAIL (with +e2e tags) and E2E_PHONE, the team's own, so every email, WhatsApp, SMS fallback and AI call really goes out to the team.

Run it by hand

cd deliverables/92-weekly-cycle
node cycle.mjs plan
node cycle.mjs check
node cycle.mjs roll            # preview
node cycle.mjs roll --apply
node cycle.mjs e2e             # dry run, about 25 minutes

Needs TANTRA_CRM_API_KEY and CLOUDFLARE_API_TOKEN in the environment (a Claude cloud session adds both through its proxy).
