Handoff: create the Cloudflare API token for the teleprompter deploy

Paste everything below the line into a new Claude session on your Mac (Claude Code in Terminal, or the Claude desktop app with Claude in Chrome). It walks you through creating the token, checks it, and gives you back the facts the cloud session needs. The token itself never goes into any chat.

You are helping Adi create a Cloudflare API token so a separate cloud Claude session can deploy the Tantra Teleprompter (card 71) to https://teleprompter.usetantra.com as a Cloudflare Worker.

What the cloud session will deploy

  • A Worker named tantra-teleprompter, with one Durable Object class Hub (SQLite storage) and static assets.
  • A Worker secret TP_PASSCODE.
  • A Workers Custom Domain teleprompter.usetantra.com. Cloudflare creates its DNS record itself.
  • Code: (in this card) on branch claude/dreamy-galileo-q3958u, folder deliverables/71-teleprompter/worker.

Rules

  • Never print, echo, log, save to a file, or paste the token value anywhere, including this chat. If Adi pastes it into chat by mistake, tell him to roll it on the token's page (Roll) and start step 4 again.
  • Adi does every click in the Cloudflare dashboard. You guide him and run only the read-only checks below.
  • Use the Brave profile Adi uses for Cloudflare.
  • No em or en dashes in anything you write.

Steps

1. Check usetantra.com is on Cloudflare

Run:

dig +short NS usetantra.com
  • If the answer ends in ns.cloudflare.com, go to step 2.
  • If it doesn't, stop. A Workers Custom Domain needs the zone on Cloudflare. Tell Adi which DNS provider the nameservers point to, and report back "zone not on Cloudflare" plus the nameservers. The cloud session will switch to another plan (a workers.dev address now, or the EC2 server files in deliverables/71-teleprompter/deploy/).

2. Find the account and zone IDs

Have Adi open https://dash.cloudflare.com and click usetantra.com. On the zone's Overview page, the right column under API shows the Zone ID and the Account ID. Write both down. They are not secret.

3. Check that nothing already uses the name

In the same zone, open DNS, then Records, and search for teleprompter.

  • If a record exists, note its type and target, and ask Adi whether it can be replaced.
  • If none exists, that is the normal case.

4. Create the token

  1. Open https://dash.cloudflare.com/profile/api-tokens
  2. Click Create Token.
  3. Next to Create Custom Token, click Get started.
  4. Token name: tantra-teleprompter-deploy
  5. Permissions. Add these rows with + Add more, one row per line:
Scope Permission Access
Account Workers Scripts Edit
Account Account Settings Read
Zone Zone Read
Zone DNS Edit
Zone Workers Routes Edit
User User Details Read
User Memberships Read
  1. Account Resources: Include, then the account that holds usetantra.com.
  2. Zone Resources: Include, Specific zone, usetantra.com.
  3. Client IP Address Filtering: leave empty. The cloud session's IP address changes, so a filter would block it.
  4. TTL: start date today. End date: 90 days from today.
  5. Click Continue to summary. Check that the summary matches the table above, then click Create Token.
  6. Leave that page open. Cloudflare shows the token only once.

5. Verify the token without showing it

Have Adi click Copy on the token, then run:

curl -s -H "Authorization: Bearer $(pbpaste)" https://api.cloudflare.com/client/v4/user/tokens/verify | python3 -c "import sys,json; d=json.load(sys.stdin); print('valid' if d.get('success') and d['result']['status']=='active' else 'NOT VALID: ' + str(d.get('errors')))"

It must print valid. Then check the token can see the zone. Copy the token again first if the clipboard has changed:

curl -s -H "Authorization: Bearer $(pbpaste)" "https://api.cloudflare.com/client/v4/zones?name=usetantra.com" | python3 -c "import sys,json; d=json.load(sys.stdin); print('zone visible' if d.get('result') else 'zone NOT visible: ' + str(d.get('errors')))"

It must print zone visible. Then clear the clipboard:

pbcopy < /dev/null

If either check fails, fix the permissions on the token's page (Edit) and run the checks again.

6. Keep the token for one hand-over

Adi copies the token into his password manager as "Cloudflare: tantra-teleprompter-deploy". He will paste it once into the secure credential form the cloud session opens. That form saves it on the cloud environment, and the cloud session never sees the value.

7. Report back

Give Adi this block to paste into the cloud session. It holds no secrets.

Cloudflare token ready: tantra-teleprompter-deploy (custom token, 90 days)
Nameservers: <output of step 1>
Account ID: <from step 2>
Zone ID (usetantra.com): <from step 2>
Existing "teleprompter" DNS record: none | <type and target, and whether it can be replaced>
Checks: verify = valid, zone = visible

Then tell Adi: "Go back to the cloud session, paste this block, and when it opens the credential form for api.cloudflare.com, paste the token there. Not in the chat."

README.md

Tantra Teleprompter (card 71)

Two phones, one script. One phone sits on the teleprompter and shows the script mirrored and flipped for the glass. The other phone is the remote: play, pause, speed, back, skip, jump to a section, text size, mirror. The desktop stays free for screen sharing.

It replaces the Elegant Teleprompter remote, which went behind a paywall on 12 Nov 2026.

Live: https://teleprompter.usetantra.com

Runs on Cloudflare (Worker tantra-teleprompter, account Growthcluborg). It works on any network, with no Mac and no shared Wi-Fi needed.

  1. Open https://teleprompter.usetantra.com and add your script: paste it, upload a .txt or .md file, or import a Google Doc shared as "Anyone with the link".
  2. Tap Generate code. The page shows the code and two QR codes.
  3. Scan Prompter with the phone on the teleprompter and Remote with the phone in your hand. Both phones are now in the same session. You can also type the code under Have a code? on any device.
  4. On the prompter phone, tap Start. That goes full screen and keeps the screen awake. Double tap the screen to bring the menu back.

The text is mirrored and flipped upside down by default, which is how it reads off teleprompter glass. Either can be switched off under Display on the remote.

Brand

Tantra's dark system from context/from-workshop-project/brand/tokens.json: ink #0b0d12 ground, volt #6d4aff for the main actions, iris #a78bfa for accents on dark, cyan #22d3ee for cues, signal #34d399 for "live". Clash Display for headings, Satoshi for everything else, including the script on the prompter. The current Tantra logo (circuit tree mark plus wordmark, white versions for dark grounds) appears in the header of every page and on the prompter's start menu, never on the scrolling text. App icons and a web manifest let people add it to their home screen as "Teleprompter".

Redeploy after a change

Never redeploy during a live session. A deploy restarts the Worker, which drops both phones' live connections for a few seconds.

The cloud environment holds the Cloudflare token as a network secret, so wrangler gets a placeholder:

cd deliverables/71-teleprompter/worker && npm install && CLOUDFLARE_API_TOKEN=proxy-injected CLOUDFLARE_ACCOUNT_ID=e51d1fda77a8f98fb670b2c106bd8a33 npx wrangler deploy

From a Mac, run npx wrangler login once, then npx wrangler deploy in the same folder. The app's files are bundled into the Worker script, not uploaded as Workers assets, because the asset upload signs with its own key, which the cloud proxy would replace. Sessions live in the Durable Object Hub, one storage key per session, so a redeploy keeps them.

To test the live site:

node test/e2e.js https://teleprompter.usetantra.com

Backup: run it on your Mac over Wi-Fi (5 minutes)

  1. Get this folder on the Mac: git pull in the workspace, then open deliverables/71-teleprompter.
  2. Double-click start.command. If macOS blocks it, right-click it, then Open. Or in Terminal:
cd deliverables/71-teleprompter && node server.js
  1. The window prints a line like On your phones: http://192.168.1.23:4400. Leave the window open. If macOS asks whether to allow incoming connections for node, click Allow.
  2. On the Mac, open http://localhost:4400, add your script and tap Generate code. You'll see two QR codes.
  3. Teleprompter phone: scan the Prompter QR. Tap Start. That goes full screen and keeps the screen awake. Place it on the teleprompter.
  4. Remote phone: scan the Remote QR. On an iPhone, tap Share, then Add to Home Screen so it opens like an app.
  5. Both phones must be on the same Wi-Fi as the Mac. The dot at the top of the remote turns green, and the red "prompter is not connected" bar goes away.

start.command runs the server under caffeinate, so the Mac doesn't sleep while you present.

Sessions and codes

  • A code is a session. Generating a code takes the script you added and makes a session for it. Every device that opens the same code joins that session.
  • Several scripts per code. Inside a session, open Add or edit scripts in this code (or Scripts on the remote) to add more and switch between them from any screen.
  • Nothing carries over. A new code starts with only the script you add for it. There are no accounts and no library across codes.
  • Sessions expire. A session nobody has opened for 7 days is deleted.
  • Codes: 6 characters without look-alikes (no 0, O, 1, I or L), not case sensitive. A wrong or expired code goes back to the home page with a note.
  • Limits: 50 scripts per code, 500 KB per script. Anyone with the code can see its scripts and control its prompter.

Scripts

  • Paste or type on the home page, or in Add or edit scripts in this code.
  • Upload file: a .txt or .md file. A webinar deck's index.html also works and gives one section per slide from its speaker notes.
  • Import from a link: a Google Doc shared as "Anyone with the link", or any page with text.

Script format:

# Section name        a section you can jump to from the remote
(blank line)          starts a new paragraph
[a cue]               shows in blue; for things you don't read out

Edits to the script on the prompter show up live, and you keep your place.

Before every webinar

  • Set the teleprompter phone's screen timeout to the longest option. The page keeps it awake too, but this is the backup.
  • Put both phones on Do Not Disturb.
  • Do a 30 second test: play, pause, speed up, back. The remote shows the round trip in ms next to the green dot.
  • If anything looks stuck, tap Display, then Reconnect on the remote, or reload the prompter. It comes back on the same line.

Your own server instead of Cloudflare

deploy/ holds a systemd unit and an nginx site for running server.js behind HTTPS on any Linux box, such as the content engine's EC2 server.

PRD: Two-phone teleprompter (card 71)

Method: gstack /spec (why, scope, technical with code reading, draft, gate). Phase 1 answers came from Adi on 12 Nov 2026. Adi then asked for a prototype the same day, so the Phase 2 scope calls below are my decisions, written down so they can be reviewed.

On 12 Nov 2026 the webinar failed because Elegant Teleprompter (Android) put its remote control behind a paywall. Without the remote, nobody can pause, slow down or rewind the script on camera. Scope

In: - Prompter page: smooth scroll, mirror left/right and upside down, reading line, text size, margins, line spacing, alignment, keeps the screen awake, full screen on one tap. - Remote page: big play/pause, speed with plus, minus and slider, direction, hold-to-repeat back and skip, jump to section, live position and time left, all display settings, a red warning when the prompter isn't connected. - Scripts: library, editor, paste, upload .txt, .md or .html, import a Google Doc link, import the deck's speaker notes. Live edits keep your place. - Rooms with codes, an optional passcode, and state saved on the server so a reload resumes on the same line. - Runs on the Mac over Wi-Fi today. The same server deploys to teleprompter.usetantra.com.

Out (separate cards if wanted): - Voice-follow scrolling (the text follows your speech) - User accounts and per-user script libraries - A native app - .docx upload (paste the text instead) - Offline mode with no server at all

Smallest valuable cut: prompter plus remote plus paste a script. Everything else here is extra, and it is all built.

Design

  • Server: server.js on Node 18+, with no dependencies. It holds one state object per room: script, playing, speed, direction, layout and anchor. Commands come in over POST /api/rooms/:room/cmd, and every phone in the room gets them over Server-Sent Events from GET /api/rooms/:room/events. The server pings every 10 s. Scripts and room state save to data/*.json.
  • Position: the prompter scrolls on its own clock (requestAnimationFrame) and reports its anchor (paragraph index plus how far through it) every 450 ms. The anchor doesn't depend on screen size, so reloads, rotations and text size changes keep the line.
  • Speed: level 1 to 30, where pixels per second = level × 0.085 × line height. Level 5 is about 0.4 lines a second, a calm speaking pace at the default size.
  • Resilience: the client reopens the stream on error, after 25 s of silence, when the page comes back into view, and when the network returns. On http, a muted inline looping video keeps the screen awake. On https, the Wake Lock API does it.

API shapes:

POST /api/rooms/MAIN/cmd   {"type":"toggle"} | {"type":"speedBy","value":1} | {"type":"nudge","lines":-2}
                           {"type":"jump","para":10} | {"type":"set","values":{"fontSize":72,"mirrorX":true}}
                           {"type":"script","id":"abc"} | {"type":"restart"} | {"type":"dir"}
POST /api/rooms/MAIN/pos   {"para":10,"frac":0.4,"progress":0.21,"atEnd":false}   (prompter only)
GET  /api/scripts, GET/POST/DELETE /api/scripts/:id, POST /api/import {"url":"..."}

Acceptance criteria

  1. A tap on the remote changes the prompter in under 500 ms on the same Wi-Fi. Test: 30 ms median, 57 ms worst over 10 taps.
  2. Play scrolls, pause holds the text still to within 1 px, and speed plus and minus change the level by exactly 1.
  3. Back and skip move the text by 2 lines per tap and keep moving while held.
  4. Jumping to a section puts that section's heading on the reading line.
  5. Reloading the prompter brings it back at the same paragraph in under 5 s. Test: 359 ms.
  6. Changing the text size keeps the same paragraph on the reading line.
  7. A script saved on one phone appears on the prompter, and edits show up live.
  8. The prompter stays awake for a full 60-minute run. This is checked on real phones in the dry run, because an emulator can't test it.
  9. Deck import produces one section per slide (74).

Effort

Built in one session: about 1 h server and protocol, 1.5 h prompter and remote, 0.5 h scripts and imports, 0.5 h tests and docs. The cloud deploy takes Adi about 20 minutes (see the README).

Decisions after launch (Adi, 13 Nov 2026)

  • Sessions and codes, no accounts. A visitor adds a script, then taps Generate code. The code is a session; every device that opens it joins. A session can hold several scripts while that code is in use. A new code starts fresh, and nothing carries over between codes. No passcode, no owner code, no preloaded scripts. Sessions unused for 7 days are deleted.
  • Mirrored and flipped by default, because that's how the text reads off teleprompter glass.
  • No countdown before play. Play starts scrolling at once.
  • Tantra branding (logo, brand tokens, Clash Display and Satoshi), so it can be offered to clients.
